# Maintenance audit

## Code and system boundaries

- One Next.js application owns company and service routes in src/app. Keep reusable controls, styles and server utilities separate from branch-specific page composition without introducing workspace/package indirection.
- Keep navigation, real route lists, canonical metadata and sitemap coverage aligned when adding pages. Search engines may index the site only on Vercel Production on the production origin (indexingAllowed in src/lib/config/env.ts).
- The canonical host is https://www.motchi.ca; README.md (Domain) describes the apex redirect and what derives from it. Keep host redirects in Vercel only, the Turnstile widget's hostname list aligned with the canonical host, and SITE_URL unset in production.
- Project media has one owner in public/media/projects. Update the typed records in src/content/websites with actual dimensions and approved content.

## Design, accessibility, and performance

- Approved content, real project media and the MS/MW/MC identities are the source of truth. Work, pricing, capabilities and approach pages serve different purposes; preserve their distinct compositions and shared controls.
- Use shared semantic tokens and original SVG marks. Solutions' compact spacing and dark/feature surfaces live in its app styles; one element should own each gap. Keep gold text on appropriately dark surfaces, with burgundy/charcoal for text on light surfaces.
- Maintain native semantics, visible keyboard focus, readable selected/hover states, minimum comfortable targets and reduced-motion alternatives. The guided contact form requires JavaScript; its email alternative must remain visible without it.
- Process stage headings wrap tightly around 1024px. Review the breakpoint and composition when refining tablet layouts.
- Screen-reader/VoiceOver, forced-colors, physical mobile devices, 200% text and 400% browser zoom need dedicated manual review. Automated tests and viewport emulation do not establish accessibility conformance.
- Keep marketing server-rendered and state in small client islands. Preserve image dimensions, lazy loading, native media controls and reduced-motion checks. Avoid adding an animation framework for small interactions. Fonts are self-hosted by Next after build-time retrieval; allow the required network access in clean builds.
- No bundle-size, Lighthouse or field Core Web Vitals improvement is assumed. Measure before optimizing. Vercel Web Analytics (src/lib/config/analytics.ts) loads only on Vercel Production builds, sets no cookies, and strips query strings and fragments before sending (contact results carry ?status and ?ref); keep the privacy policy's Visitor statistics section in step, and add no other tracker without updating it.

## Security and contact reliability

- Trusted environment access and delivery remain server-only. Keep keys, submitted messages and raw provider responses out of logs and public error output. Same-origin checks must use validated configuration rather than arbitrary Host or forwarding headers.
- Contact protection includes authoritative validation, duplicate-field rejection, a 24KB body limit, signed tokens, a honeypot, Cloudflare Turnstile verified server-side (action and hostname checked), and per-IP, per-email and site-wide limits with a duplicate-send guard (src/lib/security). Per-IP limits run before the bot check; per-email and site-wide limits count only submissions that passed it, so unverified traffic cannot lock out an address or the form. Keep that order. Limits are shared through Upstash Redis when configured; without it they fall back to process memory, which serverless hosts reset and do not share, so configure Upstash in production. An Upstash outage fails open to memory rather than blocking visitors. Visitor IPs come from x-real-ip, which Vercel sets. Do not put another proxy (such as Cloudflare's orange-cloud proxy) in front of Vercel without revisiting this: every visitor would share the proxy's IPs and per-IP limits would stop working. Turnstile protects only the form; site-wide DDoS mitigation comes from Vercel's platform, and a Vercel Firewall rate rule on POST /api/contact is an optional outer layer. The contact page checks Brevo, Turnstile and the form secret before issuing a form (prepareContactForm), so misconfiguration shows the email fallback up front.
- Visitor input in operator email: URI-encode addresses inside mailto: links (email local parts may contain ? & = % #). Contact text fields reject C0/C1 controls, line and paragraph separators, and bidi embeddings, overrides and isolates; the client filter and server validation share isUnsafeCharacter. Only labels the wizard sends (answerLabels and service names in contact-config.ts) become notification rows, each once; any other line is shown as the visitor's message. Cloudflare's always-pass Turnstile test keys are refused when VERCEL_ENV is production. The per-email limit treats plus-tag variants as one mailbox. The site-wide limit (110 enquiries a day) keeps this site within 220 of the shared Brevo account's 300 free daily emails; raise it only with the Brevo plan. Regression tests: tests/contact.test.mjs, tests/configuration.test.mjs, tests/submission.test.mjs.
- Provider timeouts can leave delivery uncertain: a Brevo error response returns `failed` (safe to retry; the claim is released), but a timeout returns `unavailable` and keeps the claim so a retry cannot send twice. Never promise exactly-once delivery or retry automatically without durable coordination. Partial acknowledgement failure must still confirm that the enquiry arrived and discourage resubmission. Verify real Brevo sender authentication, reply-to, notification and acknowledgement behavior using controlled inboxes.
- The shared CSP permits inline scripts and styles, which Next's static rendering needs. A stricter nonce policy requires request-specific nonces and compatible dynamic rendering; test hydration/navigation before enforcing it. Keep HTTPS, body limits, timeout limits and least-privilege environment access in hosting configuration. HSTS (two years, production only) and Cross-Origin-Opener-Policy are set in src/lib/config/security.ts. Review every subdomain before HSTS includeSubDomains/preload.
- Keep the privacy policy, retention practice, product status, asset permissions and security reporting inbox accurate as they change. Do not invent legal facts or product availability. Robots/noindex is not authentication.

## Owner-supplied content and compliance

- Client testimonials or quotes (with permission), a founder or team introduction with a photo on About, and consulting examples or case studies. Service sites in this field usually carry these as trust signals; add only approved, real content.
- Privacy policy (src/components/ui/privacy.tsx): have an Ontario privacy lawyer review it before relying on it. Its 12-month deletion of non-client enquiries and call bookings depends on the Google Apps Script and Gmail filters in README.md (Enquiry retention), not on app code. The script runs with reportOnly: false; run previewAll after changing labels or filters to confirm what would be deleted. It names Cloudflare (Turnstile, no cookies, Turnstile privacy addendum linked) and Upstash (United States; create the database in a US region or update the policy). It states that Brevo counts opens and clicks only anonymously (account setting Anonymous email tracking = Yes, plus contactPixelTrackingConsent: false on each recipient in src/lib/email/index.ts; full disabling needs a Brevo Enterprise request) and that the inbox and provider accounts use two-step verification; keep both true. Update the policy and its date before adding other analytics or custom events, changing providers, or changing what the contact form collects.
