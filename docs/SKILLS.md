## Modes and execution cautions

- **Security Audit:** Guidance uses only relevant material and does not create audit artifacts or start the six-phase workflow. Full audits are reserved for explicit full/comprehensive security reviews, pre-production/pre-launch reviews, major releases, major auth/backend/infrastructure changes, incidents, or significant trust-boundary changes. Upstream `quick`, `standard`, `deep`, and scoped runs are full-audit profiles, not the focused default. Keep certainty separate from severity and follow the repository's reporting/isolation rules.
- **Hallmark:** An audit is permission to review, not to redesign. Existing designs require the user to name Hallmark; upstream creation and `redesign` branches do not override approved Motchi content or task scope. `imagegen.mjs` sends a prompt and a bearer credential to `api.together.xyz`; `theme.mjs photos --save` downloads from `upload.wikimedia.org`. Browser helpers use Puppeteer/Chrome, can follow external assets, and may inspect environment-selected tool paths. Install/hook helpers can modify local or global agent locations/settings. None is implicitly authorized or advisory-cleared by installation.
- **Untangle Codebase:** Use concrete coupling/ownership evidence and a bounded requested scope. Its broad upstream workflow is not authority for a rewrite, a persistent goal, or unrelated cleanup. Other instruction-only skills have no separate operating mode (`N/A`).
- **Local-only execution:** UX Writing's packager and Security Audit's validators/tests still require the executable review policy even without direct network calls. Inspect only the relevant helper and dependencies; do not run a full audit to validate one tool call. Prefer local instructions when external access is unnecessary.
