Motchi Application Architecture

One Next.js application serves Motchi Solutions, Websites and Consulting. The numbered path follows a contact enquiry from the browser to both inboxes and back. Reflects the code on November 13, 2026; Vercel hosting is planned, not live.

  • Stays on the visitor's device
  • Secrets, server only
  • Handles personal information
  • Grey line: supporting request; dashed: configuration, not a request

Enquiry path

  1. The browser requests a page; the server returns rendered HTML, and client islands add interaction.
  2. The contact wizard posts the enquiry, with a signed form token and a Turnstile token, to POST /api/contact.
  3. After its checks (limits in Upstash, the Turnstile token verified with Cloudflare), the server calls Brevo's transactional API over HTTPS with the server-only key.
  4. Brevo delivers (a) the notification to contact@motchi.ca, with replies going to the visitor, then (b) a short acknowledgement to the visitor.
  5. The server answers with a 303 redirect carrying a status, and the result panel shows sent, partly sent, or not sent.

Trust boundaries

  • Personal information leaves the browser only in step 2, and the server forwards it only to Brevo (step 3). The spam check sends Cloudflare the visitor's IP address and browser details; Upstash holds only scrambled counters.
  • Saved drafts stay in the visitor's browser until they send; the service worker never caches pages, /api, or form posts.
  • Secrets live in host environment variables and are read only on the server.
  • The strict security policy allows scripts from motchi.ca and Cloudflare Turnstile only, and frames from Turnstile only.
  • Rate limits and duplicate-send records live in Upstash when configured, otherwise in server memory, which resets on restart. A host or Cloudflare rule on POST /api/contact is still a sensible outer layer.

Continuous integration

The quality job checks formatting, lint, types and unit tests, then builds. The browser job builds and serves production and runs the Playwright end-to-end, accessibility (axe) and layout tests on desktop and mobile, with contact delivery intercepted. Dependabot proposes npm and Actions updates weekly; both jobs must pass.
