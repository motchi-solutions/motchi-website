Browser and server boundaries

Visitor requests a server-rendered page, uses a branch enquiry or the four-step contact wizard, and submits to the Node.js contact endpoint. After server validation, Brevo sends the team notification, then attempts the visitor acknowledgement. Marketing routes are server rendered; navigation and contact interactions use client components.

Maintenance boundaries

Approved content lives in src/content. Project pages and GET /api/projects share getProjects(), which reads the local project records. Email credentials stay server-only. Rate limits and replay state are process-local, not a durable store. This view describes application code without assuming a deployment provider.
